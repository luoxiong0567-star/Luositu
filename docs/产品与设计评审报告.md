## 二、维度详解

### 1. 技术栈健康度 —— 42/50 ⭐⭐⭐⭐

**做得好的（值得保持）：**

- **零 CDN、零 ES module、全资源内联**是本项目最正确的产品决策。`file://` 直开 + 微信单文件分发的形态下，UMD Three.js r149 是唯一稳妥选择（r163 起官方移除 UMD），这个约束识别准确。
- KaTeX 连同 woff2 字体 base64 内嵌进 CSS，公式排版全程离线，执行力完整。
- 自写 OrbitControls（≈200 行）替代 jsm 依赖，左键平移 / 右键旋转 / 触屏手势统一路由，砍依赖的思路对。

**风险与短板：**

- **Three.js r149（2022）已停止维护**，未来新增效果（如后处理生态）将无官方 UMD 可升。目前自写 Bloom 管线能撑住，但这是一条逐渐变窄的路——建议在 README 中明确"版本冻结"策略，而非默认它是可升级的。
- 无 TypeScript、无 JSDoc 类型约束。`HL.registerScene` 契约、`GRAV` 素材库这类"框架级接口"全靠注释约定，第 13 个场景的作者（可能是三个月后的你自己）犯错概率会陡增。

### 2. 架构与产品设计 —— 37/50 ⭐⭐⭐☆

**做得好的：**

- **场景插件契约**（`registerScene` + create 返回 `{update, setParam, onClick}`）+ **子场景二级路由**（`GRAV.registerSub` + 动态控制面板）是本项目架构上最亮的两个设计，参数面板、资源回收、快捷键、URL 直达全部自动生效——这是"框架意识"，不是"页面堆砌"。
- **目录页（12 张 CDP 真实渲染缩略图 + 一句话简介）** 是产品力的关键一步：把"12 个孤立 demo"变成了"一个有封面、有目录的作品"。
- URL 直达参数（`?g=escape#gravity`、`?Z=26#periodic`）让它具备"可引用性"——科普讨论中可以直接甩链接到某个具体状态，这是同类作品极少做到的。

**产品力真正的缺口（按重要度排序）：**

1. **内容停留在"演示"层，未到"学习"层。** 每个场景都有公式卡片和实时读数，但用户看完动画后，"为什么 F 与 r² 成反比"这件事没有被产品教给用户。差的是一层**讲解模式**：分步引导（高亮要素 → 暂停 → 旁白文字 → 参数实验建议）。这是从"炫技"到"教学产品"的分水岭，也是本项目最有价值的升级方向。
2. **参数实验缺少"对比"与"回放"。** 例如开普勒 e=0.55 改成 0.9，用户看不到前后差异。低成本方案：每个滑杆支持"快照对比"（保存当前曲线为幽灵轨迹）。
3. **首次进入场景无引导。** 交互被反转为"左键平移 / 右键旋转"（与多数 3D 软件相反），但提示只有底部一行 hint，且 3 秒后是否消失、是否每个场景重复，没有统一策略。

### 3. 视觉与交互打磨 —— 38/50 ⭐⭐⭐☆

**做得好的：**

- 暗色深空 + 玻璃质感天体 + 霓虹线框 + 粒子拖尾，12 个场景**视觉语言高度一致**——这是设计纪律，不是巧合。KaTeX HUD 卡片 + 实时读数行让"科学仪器感"成立。
- 目录页卡片（编号角标 + 图标 + 名称 + 一句话）信息密度拿捏得当。

**短板：**

- **HUD 卡片与画布争地是系统性问题。** 本轮 binary/kepler/tidal 靠手工调相机 target.x 避让左侧 HUD——这说明"画布安全区"没有进入框架。建议在框架层定义 `HL.safeArea`（HUD 实际占宽），场景取景统一引用，一次解决、永不再调。另建议 HUD 卡片支持一键折叠。
- **配色对比度未做无障碍校验。** 深空背景上的 `#8fa3bd` 灰蓝说明文字（muted）在部分显示器上可能低于 WCAG AA。不需要大改，把 muted 提亮一档即可。
- 部分场景的"标志性瞬间"还可以更狠：引力井的小球坠入、三体混沌的扰动分岔，目前是"发生了"，但缺少**电影感的节奏控制**（慢动作、闪光、镜头轻微推拉）。

### 4. 工程化成熟度 —— 30/50 ⭐⭐⭐

**做得好的：**

- `build_single_html.py` 单入口发布 + 内联前危险字符校验，CDP 自测工具链（`_grav_test.js` 六子场景断言、`_iso_test.js` 隔离冒烟、`_thumbs.js` 缩略图再生）——**这个"手工 CI"体系是本项目最被低估的资产**，它让每次改动都有回归验证。

**短板（这是全项目最大的系统性风险）：**

- **没有 git。** `_versions/` 手工备份已经救过一次周期表 v1，但那是运气不是机制。11,600 行、27 个文件、12 个场景，一次误删或一次 Edit 静默失败（本项目已发生 ≥4 次）就可能丢失数天工作。这是唯一的 P0。
- 无 ESLint / Prettier。ES5 风格 + IIFE 的纪律目前靠自觉，一个 `var` 提升错误在 2,000 行的场景文件里会很难查。
- 无最小化测试。CDP 脚本验证"加载无异常 + 读数正确"已经很有效，但没有固化成"一条命令跑全部回归"的总入口（目前是多个脚本分别手动跑）。

### 5. 性能与可维护性 —— 32/50 ⭐⭐⭐

- 软渲染（swiftshader）下 30–60 FPS 达标，真机 GPU 无忧；1.89 MB 单文件本地 `file://` 秒开。**当前没有性能事故。**
- 风险在于**无性能分级**：440 粒子布朗运动 + shader 液面 + InstancedMesh 晶格 + Bloom 全开的重场景，在老核显笔记本上叠加时会掉帧。建议按 `navigator.hardwareConcurrency` / 首帧 FPS 探测做三档（完整 / 均衡 / 简洁：粒子减半、关 Bloom）。
- 单文件 1.89 MB 中 KaTeX 占 628 KB（33%），但只有 gravity 场景用公式。若未来体积成为顾虑（如微信传输限制），可做"按需内联"变体——但当前体量下**不建议现在做**。

## 三、改进优先级表

| 级别 | 改进项 | 预期收益 | 估算工时 |
|---|---|---|---|
| **P0** | **git 初始化 + 提交纪律**（当前无任何版本机制，Edit 静默失败已发生 ≥4 次） | 消除数据丢失这一唯一致命风险 | 0.5 h 初始化 + 习惯 |
| **P0** | **场景首次引导浮层**：统一"操作提示 3 秒淡出 + 首次访问高亮 hint 条"，覆盖交互反转说明 | 新用户 10 秒内理解操作范式 | 4 h |
| **P1** | **讲解模式（分步旁白）**：在 gravity（6 子场景）试点"讲解模式"按钮——分步高亮要素 + 暂停 + 文字解说 + 参数实验建议 | 产品从"演示"升级为"教学"，核心产品力跃迁 | 2–3 天（试点） |
| **P1** | **框架层画布安全区**：`HL.safeArea` 统一取景，HUD 一键折叠 | 一劳永逸解决 HUD 遮挡，新场景不再手工调相机 | 0.5 天 |
| **P1** | **竖屏提示层**：手机竖屏时显示"请横屏体验"遮罩（不是做响应式，只是礼貌提示） | 手机首次打开体验止损，成本极低 | 2 h |
| **P1** | **回归总入口**：一个 `verify.js` 串起 `_grav_test / _iso_test / _chk_thumbs`，发布前一条命令 | 发布信心 + 5 分钟内出全量结论 | 2 h |
| **P2** | 性能三档分级（完整/均衡/简洁，首帧 FPS 探测自动选档 + 面板手选） | 低端设备兜底 | 1 天 |
| **P2** | muted 文字提亮一档 + HUD 对比度自查（WCAG AA） | 长时间阅读舒适度 | 1 h |
| **P2** | 参数"快照对比"（滑杆改动前后轨迹幽灵叠加） | 实验教学价值 | 1 天 |
| **P2** | 托管发布时的 favicon / meta description / 分享标题（file:// 场景下无意义，上 https 托管时再做） | 网页分享卡片观感 | 1 h |

**不建议做的（明确劝退）：**
- ❌ 响应式重构——已决策"手机浏览器直接打开"，本报告尊重该决策；竖屏提示层是止损，不是翻案。
- ❌ 引入 Vue/React/打包器——单文件离线形态是本产品的立身之本，引入构建链是负优化。
- ❌ 现在"按需内联 KaTeX"——1.89 MB 未构成实际传输瓶颈，属于过早优化。

## 四、总结

**71.6 / 100 · ⭐⭐⭐☆**——以个人作品论，这是一个**完成度和工程质量都显著高于平均水平**的产品：插件化架构、真实渲染缩略图目录、物理读数全自洽、离线单文件分发，每一项都是同类作品里的稀缺能力。

差距集中在三点，且都有明确路径：**工程上缺 git（半天可解）、体验上缺引导（4 小时可解）、产品力上缺讲解模式（2–3 天试点）**。其中讲解模式是唯一能把作品"从好看变成有用"的升级，建议作为下一个迭代的主题。

> **免责声明**：本报告基于静态分析和经验规则生成，FPS 数据来自 headless 软渲染环境，仅供参考；实际改进决策请结合使用场景与投入意愿综合判断。架构没有银弹，合适的才是最好的。
